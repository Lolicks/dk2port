# План реализации собственного декодера

Этапы идут по зависимости: сначала контейнер и распаковка, потом модели, потом
видео/звук, потом текстуры и интеграция. Каждый этап имеет проверяемый критерий
на реальных файлах из `Dungeon Keeper II`.

## Этап 0 — каркас (0.5 дня)

- Создать `decoder/core` (reader/buffer/endian/error) и CMake/CLI-каркас.
- Критерий: все unit-тесты reader проходят на синтетических буферах.

## Этап 1 — WAD (1 день)

- Порт `Dk2Wad` по `WAD_FORMAT.md`; list/extract, flags 0/4.
- Критерий: 5 WAD → 102/445/2015/81/24 записи; 31 дубликат в FrontEnd
  корректно различается по индексу; names pool заканчивается в EOF.

## Этап 2 — KMSH (1 день, самый ценный)

- Порт `dk2_kmsh_decompress` по `KMSH_FORMAT.md`.
- Критерий: 2015/2015 записей Meshes.WAD → выход точной длины `u32@10`;
  первые 4 байта `KMSH`; внутри — валидный `HEAD`.
- Текущий Python-эталон уже есть: `tools/kmsh_decompress.py`.

## Этап 3 — KMF (2–3 дня)

- IFF-обход + HEAD, MATL/MAT2, MESH/GEOM/SPRS/POLY/VERT, ANIM/ITAB/VGEO, GROP/ELEM.
- Критерий (из `kmf_catalog.json`): 2015/2015 парсятся; MESH 862, ANIM 1145,
  GROP 8; 46 660 чанков; 6 492 материала; 818 уникальных текстурных имён;
  5 112 121 вершина; 2 853 857 треугольников по всем LOD.
- Экспорт в простой intermediate format (JSON/binary) для движка.

## Этап 4 — TGQ/TQI (5–10 дней, самый сложный)

- Контейнер: SCHl/pIQT/SCCl/SCDl/SCEl, 8-байтовый заголовок кадра.
- TQI: VLC-таблицы (`FUN_005B21E0`), маски (`FUN_005B2450`), IDCT
  (`FUN_005B1D7E`), DWORD-выравнивание 10-битных коэффициентов, motion vectors
  из Ghidra (в OpenKeeper их нет).
- Критерий: первые 3 кадра `BullfrogIntro.tgq` дают 320×480 RGB, совпадающие
  по контрольной сумме с эталонными PNG из `tools/tgq_decode_openkeeper.sh`
  (`a8c4184d…4f1`, `0da6fda1…31b`, `a5f47d59…b8`).
- Резерв: если точное совпадение недостижимо, использовать OpenKeeper Java
  как offline-инструмент генерации PNG и встроить только готовые PNG в бандл
  (без runtime-зависимости от Java).

## Этап 5 — Звук SDT / EA XA ADPCM (2 дня)

- SDT: 108 банков, 5512 сэмплов, 40-байтовые заголовки.
- XA ADPCM: `(payload-12)/30*28` блоков, 16 087/16 109 совпадений по probing.
- Критерий: декодировать 10 случайных сэмплов в PCM16, сравнить с mpg123/WAV.

## Этап 6 — Текстуры (3–5 дней)

- Порт `Dk2TextureDecoder` и `EngineTextureDecoder` ( Nichols/magic tables).
- Критерий: декодировать 10 текстур из `EngineTextures.dat/.dir` и сравнить
  с уже извлечёнными PNG из `EngineTextures.WAD`.

## Этап 7 — Интеграция и тесты (2 дня)

- CLI-утилиты, unit-тесты на реальных файлах, CI.
- Критерий: `ctest` проходит; IPA собирается на macOS runner.

## Риски

| Риск | Митигация |
|---|---|
| Точность float IDCT в TQI | Etalon PNG из OpenKeeper + сравнение SHA |
| Отсутствие compress (обратной записи) WAD | Не требуется: только чтение оригиналов |
| Различия версий KMF | v17 покрывает 2015/2015; другие версии — unknown |
| Размер бандла 817 МБ | Стриминг/сжатие текстур на этапе импорта |
